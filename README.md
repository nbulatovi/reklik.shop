# ReKlik.shop

Serbian electronics storefront for refabrikovani uređaji: complete crawlable HTML on GitHub Pages, with inventory, orders, payment verification and administration on the owner's PC.

## Running services

`reklik-server.service` serves the application on `127.0.0.1:4340`; `reklik-tunnel.service` provides an isolated HTTPS Cloudflare quick tunnel. The tunnel is separate from the existing GCC Help, Topkvote and Mayaki tunnels. On a tunnel restart its endpoint is automatically republished in `docs/backend.json`.

The production server service sets `REKLIK_SECURE_COOKIES=1`: its loopback listener is exposed exclusively by the HTTPS tunnel, so external origin checks and partitioned Secure cookies use HTTPS even if cloudflared omits the forwarded scheme. Embedded browsers that block cookies receive a first-party window link before form entry.

The GitHub Pages entry point is `/docs`. Checkout, confirmation and admin pages frame the PC application. Public category and product pages contain full HTML and JSON-LD outside frames so they remain crawlable. A frame keeps the storefront address in the browser; it does not conceal the underlying network endpoint.

```sh
systemctl --user status reklik-server reklik-tunnel
journalctl --user -u reklik-server -u reklik-tunnel -n 80
/home/bg/.local/state/reklik/venv/bin/python tests/test_store.py
/home/bg/.local/state/reklik/venv/bin/python publisher.py
```

## Private state

All live state is outside the repository in `~/.local/state/reklik/`:

- `store.sqlite3`: inventory, categories, orders, sessions and audit records; SQLite WAL and transactional stock reservations.
- `private.json`: salted administrator password hash and signing secret, mode 0600. No plaintext admin password is stored in the repository.
- `uploads/`: original published WebP photographs, with metadata stripped.
- `addresses.sqlite3`: local RGZ address register, not customer data.
- `backups/`: rotating hourly database snapshots, last 48 snapshots, private permissions. Photograph files remain in uploads; these local snapshots are not an offsite backup.
- `ai-auth/`, `ai/`, `ai-rollback/`: isolated editor credentials, working copies and rollback copies. Never publish these.

Whop credentials are read at runtime from the existing `~/.secrets/electricians.env` (override with `REKLIK_PAYMENT_ENV`). They are never placed in browser JavaScript, public HTML, Git or the AI workspace. Card numbers are entered only on Whop hosted checkout; this server never receives them.

## Product browsing and item pages

Desktop browsing puts brand, large contact number, search, categories and filters in a side rail; products begin near the top edge. Mobile uses a compact two-column header and floating filter control. Product pages show a photo carousel, main specifications, price, Buy now and Add to cart together. Mobile purchase controls stay fixed at the bottom. Whole-number prices omit zero decimals while genuine fractional amounts remain exact.

The live catalog is managed by the owner. Products are ordinary saleable stock without special example labels or checkout restrictions. Card checkout is live and charges the shown amount only if confirmed. ReKlik.shop has active HTTPS and indexing.

Browser QA uses temporary state and explicitly disables publishing. It must never export its temporary catalogue into the live repository.

## Item view statistics

Opening an individual item page makes a cookieless request to the PC backend. Admin shows distinct IP counts per item across all time. The database stores a product-specific keyed HMAC of the normalized address and first-seen time, never a raw IP for this counter. Cloudflare's connecting-IP header supplies the address; IPv4-mapped IPv6 forms normalize together. Repeat visits cannot increment the item twice. Known crawler user agents are excluded. A shared IP counts once; an IP change counts separately. Counts are private, excluded from public catalogue JSON, and removed with product deletion. Privacy text describes this first-party feature; no third-party analytics service is used.

## Inventory specifications and photographs

Admin enters known specifications manually. After saving, durable background Codex research adds **only missing** manufacturer-supported facts; no lookup runs while the owner is typing the model. The current manual values always win, including edits made while research is running. Equivalent labels (CPU/Procesor, RAM/Memorija and disk/storage/SSD) use consistent Serbian formatting. Research receives known specifications, does not infer an individual configuration from model-family variants, and caches separately for different manual configurations. Description fills only when blank. Manual descriptions, photos, prices, stock and visibility stay protected. Pending jobs resume after restart; “Sačuvaj i dopuni nedostajuće specifikacije” explicitly retries research. Primary-source links and research output stay in private state. The research worker uses isolated CLI state, Bubblewrap, a web-only hook and schema-constrained output, without payment credentials or customer information.

New devices are visible by default and use “Refabrikovano - odlično stanje (Grade A)”. Six exact Serbian condition choices, including the owner's two distinct Grade B descriptions, are defined in inventory_rules.py. The one-time migration considers the old condition and description, preserves actual Novo entries and maps visible wear conservatively. Use “refabrikovani” in all future storefront copy; schema.org retains its required RefurbishedCondition enum and uses NewCondition for Novo.

Grades are fully wrapped outside photos in catalog cards and product pages. Admin uses six multiline radio choices and shows the complete grade in each inventory row. Layout QA covers every grade on 320, 390, 768 and 1440px widths. Rows offer Uredi, Dupliraj, Sakrij/Prikaži and Obriši trajno. Duplication copies specifications, photos and both prices, creates a permanent new ID/URL and sets quantity one. Hidden products leave the public catalog, categories, search and sitemap after export; their product URL returns 404 rather than a disabled listing. A refreshed cart removes hidden products and excludes them from its checkout payload. The hide/show QA checks real generated HTML, JSON, sitemap, search, stale carts and restored URLs with disposable inventory. Permanent deletion requires confirmation and a current revision, removes AI/view rows and deletes photo files only when no other product uses them. Historical order snapshots are retained. Deleted IDs are never reused, including IDs referenced by historical orders.

Repeated camera and gallery selections accumulate up to 10 photos. New uploads retain full pixel resolution in metadata-free JPEG originals under private uploads/full; optimized WebP previews stay at most 1600px. A product-photo click opens a full-screen viewer with arrows, 100% zoom, scrolling and original-image link. Older uploads retain their previously stored resolution. Only active product originals and previews are exported. The CLI research and photo checks use isolated state and cannot modify the live catalog.

## Admin operation

Use the Admin button at the bottom of the home page, or `/admin/` on the storefront. Inventory supports creating, editing, unpublishing and duplicating products; camera capture and gallery uploads work from phones. A published product needs a real photograph. The interfaces were exercised at 320, 390, 768 and 1440 CSS pixels; form fields use at least 16px text and 48px controls. Rear-camera capture, repeated photos, removal, upload, AI research and save were tested on the USB-connected Android 15 phone in Chrome 137. Automated mobile tests also cover saving during a slow lookup and later enrichment after leaving the form. A real isolated manufacturer lookup queued in 0.039 seconds and completed after 24 seconds without changing price or stock. New categories receive stable public URLs and are added to the sitemap automatically. Stock revisions prevent an old editing form from overwriting a newer sale.

Inventory stores `base_price_cents` privately and `price_cents` as the public list price, both in EUR minor units. Admin enters only the base price. List price is computed once on save as `ceil(base × 1.05 / 5) × 5` EUR with integer arithmetic, stored in the database, and shown read-only in admin. The one-time migration treats previous inventory prices as base prices and computes the new list prices without changing stock/photos/specifications or existing orders. Public HTML, JSON and SEO include only list prices.

The catalog and cart always display EUR; currency switching and manual FX editing were removed. New checkout quotes and card/COD/pickup orders use RSD. `rates.py` fetches the official NBS CurrentMiddleRate page in the background, validates EUR/978/unit 1 and the list date, and stores a last verified rate with source/date. It refreshes hourly and at the 08:00 Belgrade publication boundary, retrying failures after five minutes. Checkout performs no exchange-rate network request. Missing/unverified or more than seven-day-old lists block new quotes rather than inventing a rate; weekends/holidays can use the last published list. Shipping and warranty costs retain their RSD amounts. Each new order stores its applied rate, official date/source, EUR equivalent and EUR product prices. Checkout, confirmation, receipts and merchant alerts explain the conversion; old orders preserve original currency and totals. A changed price or rate at submission requires the buyer to review the new total.

On 23 October 2026 a live test checkout configuration was created and retrieved from Whop in RSD (120 RSD test amount), confirming RSD support; no actual card was charged. USD fallback is therefore unnecessary. The NBS source is https://webappcenter.nbs.rs/ExchangeRateWebApp/ExchangeRate/CurrentMiddleRate .

Shipping settings include Post Express, AKS and D Express independently. Each has its published weight bands; admin can update the bands, enable/disable or rename a carrier, and change an optional coefficient. Category fixed prices override the carrier calculation for that category; a blank field uses the weight tariff. In a mixed cart, the highest applicable fixed price and automatic combined-weight tariff apply. A fixed value of zero is free shipping when all cart categories have fixed prices. Shipping uses packed product weight, otherwise the category's estimated weight. Enter the carrier's chargeable weight if volumetric weight is higher.

Domestic defaults are published base carriage tariffs, not carrier bookings or contracted merchant discounts. COD-specific charges are absorbed by ReKlik; do not instruct a courier to collect more than the customer's agreed order total. Declared value, oversize and other carrier fees must be absorbed when not already included in a displayed total. Automatic Post Express calculation stops above 20 kg; AKS and D Express stop above 50 kg rather than assuming acceptance.

Order addresses are free text. Serbian Latin, Cyrillic, common ASCII spellings and villages without a street are supported. Postcode is optional but, if supplied for Serbia, must contain five digits. The order remains NEW until a person calls the customer and marks it CONFIRMED; dispatch is blocked before that confirmation. Card orders also need processor-confirmed payment. Orders and printable/downloadable confirmations are stored durably. Merchant alerts are queued atomically with each new order and sent in a separate background worker to the same `email` setting shown on the storefront. Verified card payments queue a second, distinct alert; unpaid card alerts explicitly say not to ship. Duplicate submissions cannot create duplicate queue entries, and delivery failures retry with backoff after restart without blocking checkout. Admin shows sent/pending status, and its contact email field controls both public contact and alert destination. Private relay configuration is in `~/.local/state/reklik/notifications.json`; the existing authenticated mail relay uses the ReKlik.shop display name and the customer email as Reply-To. A live test email to support@phonerepairteam.com was accepted by the provider on 20 October 2026; inbox receipt is not independently confirmed. The site does not currently send automatic customer emails or book shipments automatically.

## Payments and stock

Buy now skips the cart. COD checkout is one guest page with no account or marketing signup. Card checkout sends the customer directly to Whop after the delivery form. A returned URL never marks an order paid: company, plan, currency, total, payment status and unique payment ID are verified server-side. A background worker reconciles pending/expired card orders; the order page can request verification as well. Signed webhook support is available when `WHOP_WEBHOOK_SECRET` is configured, but reconciliation does not depend on webhooks or an unchanging tunnel URL.

Card orders reserve stock for 30 minutes. Expiry/cancellation releases stock once. A late payment with unavailable stock enters manual review and is never automatically fulfilled. Refunds are handled in the merchant dashboard; cancelling a paid order does not itself issue a refund. Never cancel shipped stock back onto the shelf before a return is received.

The admin payment check creates a **real charge**, RSD 120.00. It is explicitly labelled, contains no physical inventory and is not a sandbox. No charge occurs until the payer enters a real card and confirms the processor's payment. Sandbox/test card numbers must not be entered in this live checkout. The existing shared processor account currently displays “Nikola’s Electric”; the store does not rename that shared account. ReKlik checkout configurations disable adaptive currency conversion, enable cards and Apple Pay on the inline plan (the top-level method configuration only applies to setup mode), limit each order to one purchase, and use the processor-required `WHOP*REKLIK SHOP` statement descriptor.

Apple Pay uses the same top-level Whop-hosted payment redirect as cards, with no embedded wallet or ReKlik DNS/domain changes. Plans explicitly enable `card` and `apple_pay` and disable platform-default expansion. Eligible customers choose Apple Pay on Whop; availability depends on their wallet, browser, card, currency and processor support. A return URL still cannot mark an order paid. Wallet display/authorization and a settled charge require an eligible real Apple Wallet and have not been independently tested from this PC. Whop sandbox does not show Apple Pay. Admin’s existing RSD 120 real-payment test can exercise the wallet on an eligible device; it charges only after the payer explicitly confirms.

Official references: https://docs.whop.com/api-reference/checkout-configurations/create-checkout-configuration and https://whop.com/blog/apple-pay-whop/

## International shipping

There is one international switch, OFF by default. No per-country admin controls. Do not enable it until the Serbian exporter/invoice/customs arrangement, destination requirements, sanctions/export controls and the carrier's acceptance of refabrikovani devices with installed batteries have been resolved. The switch is not a legal clearance or a guarantee that every destination is served. International COD is disabled. Estimates use DHL Express service-point references with a 25% fuel/packing buffer, weight adjustment and editable category multiplier. Destination duties/taxes are excluded and disclosed before purchase. Pošta air services must not be used automatically for battery devices.

## Address register

Source: Republic Geodetic Authority (RGZ), Address Register, downloaded 2026-10-20, 2,491,067 active rows. Licence: Serbian Open Data Licence, https://data.gov.rs/sr/terms/ . Attribution is included on the privacy page.

Dataset: https://data.gov.rs/sr/datasets/adresni-registar/

Original ZIP URL: https://download.geosrbija.rs/download-api/opendata-proxy/export?category=ar&layer=kucni_broj_ar&geometry=true&fileName=kucni_br_csv&format=csv

Import with `python addresses.py /path/to/archive.zip`. Import is atomic. Only active records and canonical address fields are retained, with script/diacritic normalization for exact matching. Suggestions require one unique normalized street + complete house number + locality/municipality match. Ambiguous matches return no suggestion. No fuzzy matching, silent correction, street dropdown or external customer-address lookup is used. RGZ has no postcode field; no postcode verification is claimed.
